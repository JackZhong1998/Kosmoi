# Cast Builder 通用角色资产

用中文完成确认，用目标模型适合的英文 Prompt 创建可复用角色资产。角色资产阶段决定“做什么”，当前 Agent 的工具能力决定“直接出图”还是“只交付 Prompt”；两者不得混为一谈。

## 两条正交路线

先选择资产模式：

- Mode 0：新角色定脸与标准身份卡。
- Mode 1：服装定妆。
- Mode 1B：单一区域造型细节卡。
- Mode 2：三格角色表。
- Mode 3：高精度面部特写。
- Mode 4：两参考图换装。

再选择交付方式：

- DIRECT：当前 Agent 有真正返回图片的工具，且支持本步所需的文字输入、参考图数量与职责、画幅和编辑方式。
- PROMPT_ONLY：没有生图工具、工具能力不足、模型无法核验、认证失败，或用户只要 Prompt。

不要让用户先选交付方式。先做只读能力检测；DIRECT 不成立时自动进入 PROMPT_ONLY，并写明“尚未调用模型”。

## 能力闸门

在写最终 Prompt 或调用模型前依次检查：

1. 是否存在真正返回图片的 renderer；提示词 Skill 不等于生图工具。
2. 本步是否需要文生图、单参考、双参考、多图编辑、指定画幅、分辨率或输出数量。
3. 工具能否满足全部必需能力。不得静默丢参考图、颠倒职责、改画幅或减少输出。
4. 工具是否能核验准确的公开模型名或模型 ID。无法核验时不得把未知托管模型当成目标模型执行，直接转 PROMPT_ONLY。
5. 只在确定目标模型后读取对应适配器并编译 Prompt。不得用一段万能 Prompt 同时投喂三个模型。

能力检测不得通过付费试生成，也不得为探测能力上传用户参考图。

## 公开模型职责

| 公开模型 | 默认职责 | 不承担的职责 |
| --- | --- | --- |
| Nano Banana Pro，API ID gemini-3-pro-image | 标准身份卡、服装基准、三格角色表、双参考换装；复杂角色资产的默认执行器 | 不负责替用户选择候选脸 |
| GPT Image 2，API ID gpt-image-2 | 候选脸探索、造型细节卡、面部特写；能力满足时可作为用户明确选择的替代执行器 | 未经确认不替换 Nano Banana Pro 路线 |
| Midjourney V8.2 | 无参考图的候选脸与审美方向探索 | 默认不产出权威身份卡，不承担 Mode 1、2、4 |

用户明确指定模型时优先服从；若指定模型缺少本步必需能力，说明冲突并转 PROMPT_ONLY，不静默换模型。

## 资产状态机

保持唯一权威链：

    文字规格
      → 可选候选脸
      → 用户选中的唯一候选
      → 用户批准的标准身份卡
      → 用户批准的单套服装基准
      → 三格、细节卡、面部特写或换装衍生资产

状态只报告证据支持的最高一级：

    spec_locked → prompt_ready → submitted → candidate_received → user_approved

候选图不能直接进入 Mode 1 或 Mode 2。只有用户批准的标准身份卡可以成为后续身份来源；只有批准的服装基准可以进入 Mode 2。模型返回图片不等于用户批准。

## 最少确认

信息完整时不重复提问。缺少关键状态时只问：

“你要做定脸、服装定妆、角色表、面部特写还是换装？角色是从零建立，还是已有稳定身份参考图？”

在首次完整 Prompt 或付费调用前，用一张锁定卡合并确认：

- 当前 Mode 与本步产物。
- 目标模型与交付方式。
- 参考图清单和逐张职责；无图写“纯文字构建”。
- 角色身份、完整 Look、背景、构图、画幅、尺寸和数量。
- 必须保留、只允许改变和验收条件。

最后问：“以上锁定，可以开始写 Prompt 或执行本步吗？”用户未确认时不输出最终 Prompt、不调用模型。对同一已批准执行包做轻微文字修改时可直接修订。

身份锁定所需的发色、脸型、眼色或永久标记等关键字段缺失时，用一个合并问题补齐。其余未提供字段写“未指定，最终 Prompt 省略”，不得用“自然”“标准”“普通”“非夸张”或审美常识替用户补出五官、发色、体型、妆面或标记。

## 按需读取

- Mode 确定后读取 references/mode-contracts.md。
- 需要完整英文模板时读取 references/prompt-templates.md。
- 目标为 Nano Banana Pro 时只读 references/adapters/nano-banana-pro.md。
- 目标为 GPT Image 2 时只读 references/adapters/gpt-image-2.md。
- 目标为 Midjourney V8.2 时只读 references/adapters/midjourney-v8-2.md。
- 不要同时加载三个模型适配器，除非用户明确要求比较三个版本。

## 执行与交付

两种交付方式都先编译同一份执行包：

- Mode、本步产物与资产版本。
- 参考图 R1、R2 等稳定逻辑名及职责。
- 对应模型的完整 Prompt。
- 画幅、尺寸、数量和界面或 API 设置。
- 必须保留、只允许改变和验收条件。

DIRECT：

- 只调用用户已授权且能力核验通过的工具。
- 调用后记录实际模型名或“名称未暴露”、实际参数、job ID 或 provider 状态（如有）。
- 只有收到图片资产才写 candidate_received；把图片、可复用 Prompt 和下一门槛一起交付。
- 不自动把候选升格为权威资产，不自动进入下一 Mode。

PROMPT_ONLY：

- 输出目标模型、参考图上传顺序、界面参数、一个无槽位的完整英文 Prompt 和验收条件。
- 明确状态为 prompt_ready、模型调用为“尚未调用”，并写明未执行原因。

## 错误与停止

- 认证、额度、网络或服务端错误：保留原始错误和同一 Prompt，不擅自换模型或改 Prompt。
- 超时且可能已提交：标记 submission_unknown；先凭 job ID 查询，不立即重投。
- 审核拦截：不把平台状态改写成“用户违规”；只提供一次最小安全修订，等待确认后再试。
- 一次经用户确认的重试仍失败：停止并报告，不连续自动消耗额度。
- 结果身份漂移、构图错误或细节丢失：仍是失败候选；把缺陷转成可检查约束，重试前再次确认。

## 硬边界

- 不出现任何平台私有模型别名，只使用已核实的公开模型名称或 API ID。
- 不猜模型映射、工具权限、费用、审核原因或生成成功状态。
- 不添加未确认的纹身、首饰、妆面、美甲、服装或永久标记。
- 不用真人、公众人物或受保护角色名称代替可见特征说明。
- 不把一张参考图同时模糊地指定为身份、服装、姿势和风格来源。
- 不输出含未替换参数槽的最终 Prompt。
